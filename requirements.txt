# passlib 1.7.4 (the latest released version — passlib has had no release
# since 2020) reads bcrypt.__about__.__version__ and expects bcrypt's own
# internal self-test (detect_wrap_bug) to tolerate a >72-byte probe string.
# bcrypt 4.0+ removed __about__ and started raising ValueError on >72-byte
# input instead of the old silent-truncate behavior, breaking passlib's
# backend init outright. Confirmed directly in this environment: bcrypt 5.0.0
# fails tests/test_three_solution_rounds_auth_foundation.py::test_auth_login_verifies_password_and_role
# with `ValueError: password cannot be longer than 72 bytes` raised from
# inside passlib's own self-test; bcrypt 3.2.2 does not hit this path and the
# same test passes, full suite re-run showed no other change. Pin below the
# breaking major version until passlib ships a compatible release.
passlib[bcrypt]>=1.7.4
bcrypt<4.0.0
